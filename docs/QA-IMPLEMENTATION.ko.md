# AX-QA 반영 내역

2026-10-05 KST · 구현 버전 1.2.0

## 기준 자료와 범위

현재 프로젝트는 package.json 1.0.0, 기존 테스트 34개입니다. AX-QA 보고서는 다른 1.1.1 소스와 기존 테스트 80개를 대상으로 작성되었습니다. 따라서 누락된 소스를 복원했다고 주장하지 않고, 현재 파일을 기준으로 결함 수정과 필요한 업무 기능을 구현했습니다. AX-QA의 원본 보고서·로그·재현 스크립트는 변경하지 않았습니다.

## 결함별 반영

| 항목 | 반영 내용 | 검증 |
| --- | --- | --- |
| F01 저장 HTML 행동 주입 | 관리자 모달 제목/설명을 이스케이프 | VM 검사 + Ego Lite 실제 DOM에서 주입 버튼 0개, 기존 할 일 변화 없음 |
| F02 역할 응답 역전 | 요청 순번·역할·대상을 확인하고 최신 응답만 반영, 전환 즉시 이전 데이터 제거 | 응답 B→A 순서 완료 시 B 유지 |
| F03 가입 후 이전 대상 선택 | 생성 ID를 이동 URL에 명시하고 저장소보다 우선 적용. 대상이 없으면 오류 표시 | 저장소 쓰기 실패·이전 ID 잔존 시 새 대상 선택, 없는 ID 자동 대체 금지 |
| F04 응답 유실 재시도 중복 | 폼별 요청키, SQLite의 요청키/본문/결과 영속 저장과 엔터티 생성의 원자적 처리 | 동일 키 재시도·병렬 요청·재시작 후 동일 ID, 다른 본문 409, 새 키는 별도 가입 |
| F05 빈 결과물 승인 | 제출·승인 상태에서 trim 후 비어 있는 결과물 거부 | API 제출/승인/완료 차단, 관리자 폼 공백 차단, 잘못된 복원 거부 |
| F06 인프라 견적 모순 | 포함 설치비 ≤ 총액, 장비 수량 정수 | PATCH·복원 거부 및 기존 상태 보존 |
| F07 저장 후 갱신 오류 유실 | 저장 성공과 재조회 실패 분리, 모달 밖 안내와 조회 전용 재시도 | VM 및 실제 브라우저에서 닫힌 모달 밖 경고 확인 |
| F08 저장소 차단 시 중단 | 관리자 저장소 접근 예외 처리, 메모리 유지와 안내, 관리자 복구 경로 보호 | getItem 예외에서도 API 초기 요청 실행 |
| F09 금액 상한 불일치 | 관리자 금액 상한을 API/포털과 같은 10^15원으로 조정 | 기존 2×10^12원 견적이 편집 상한 이내 |

## 추가 구현

- 견적의 별도 고객 공유 승인과 해제. 공급사 내용 변경 및 담당자 변경 시 공유 자동 해제.
- 추천코드 가입, 최초 추천 정보 보존, 현재 담당자 변경, CRM 추천 링크 및 귀속 표시.
- 수요기업 상담 페이지, 접수번호와 검토 할 일의 원자적 생성, 동일 의뢰 재접수 시 중복 방지.
- 공급사 서비스 유형의 모든 2개 조합 보존, 백업의 schemaVersion 전달, 등록 시점의 날짜·연도 기본값.
- 추천코드 등 확정적인 입력 오류는 수정 후 새 키로 재제출 가능. 결과를 알 수 없는 네트워크 오류는 기존 입력/키로 재시도.

## 검증 결과

Node.js v25.4.0에서 `node --test tests/*.test.mjs`: **81개 통과, 0개 실패**.

- 기존 34개 테스트. 빈 결과물 승인에 의존하던 두 픽스처에는 실제 설명을 추가했습니다.
- API 적대적 회귀 28개: 원본 26개를 복사하고 B01을 요청키 계약에 맞게 수정, 재시작/키 충돌/병렬 재시도와 잘못된 백업 검사를 추가했습니다.
- UI 적대적 회귀 19개: 결함 재현 성공이 아니라 수정 후 기대 동작을 검증합니다.

원본 API 스크립트 그대로 실행한 기록은 **25/26**입니다. 남은 B01은 요청키 없이 같은 본문을 두 번 전송합니다. 같은 회사의 별도 정상 가입을 임의로 합치지 않기 위해 무키 요청은 별개 생성으로 유지했습니다. 수정된 가입 UI는 요청키를 전송합니다. `tests/adversarial-api.test.mjs`는 그 계약을 명시적으로 검증합니다.

원본 UI 스크립트는 결함이 재현되면 통과하는 검사이고 현재 프로젝트에 없는 `case-kpis.js`를 요구하므로 전체 통과 지표로 쓰지 않았습니다. 회귀 복사본에서는 해당 KPI 검사를 제외했습니다. 원본의 80개 테스트나 1.1.1 전체 기능을 복원했다는 의미가 아닙니다.

Ego Lite 실제 브라우저에서 추천 가입→새 대상 상담→접수를 수행했고, HTML 주입 문자열의 DOM 처리와 저장 후 GET 실패 안내를 확인했습니다. 주요 9개 경로를 1440px/390px 너비에서 확인했으며 문서 가로 넘침은 0건입니다. 검사에 임시 SQLite/4319 포트를 사용했고 기존 업무 DB를 사용하거나 초기화하지 않았습니다.

## 남은 경계

- 로컬 데모 역할은 실제 인증·기업별 보안 경계가 아닙니다.
- 자유텍스트의 이메일/전화번호 자동 차단이나 결과물의 영업 사전 승인 단계는 없습니다. 견적 공유 전 문구 검토 안내를 추가했으며, 구조화된 연락처 필드 제거와 완전한 직접 연락 방지를 구별합니다.
- 새 페이지에서 시작하는 가입은 별개 요청입니다. 네트워크 오류 후에는 기존 폼에서 재시도해야 합니다. 요청키 매핑은 서버 재시작 후 유지되지만 업무 JSON 백업에는 포함되지 않습니다.
- 기존 DB의 새 규칙 위반 자료는 임의로 고치지 않습니다. 먼저 내보내고 증빙을 정정해야 합니다. 기존 공유 필드 없는 견적은 담당자 검토 후 명시적으로 공유하세요.
- 브라우저 검사는 지정 시나리오와 화면 크기 확인입니다. 모든 접근성·브라우저·운영 환경의 검증은 아닙니다.
