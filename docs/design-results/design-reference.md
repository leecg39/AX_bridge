# Thumbtack 웹 디자인 시스템

> 대상: https://www.thumbtack.com/  
> 조사일: 2026-10-05 · 문서 언어: 한국어  
> 목적: Thumbtack 홈페이지의 시각 규칙을 다른 프로젝트에서 재현하고 확장하기 위한 구현 명세

## 1. 사용 범위와 근거

이 문서는 **현재 홈페이지에서 수신한 HTML·CSS**와 **Thumbtack의 공식 디자인 시스템인 Thumbprint**를 함께 분석했다. 핵심은 생활 공간 사진, 큰 제목, 대화형 검색, 신뢰 정보, 서비스 탐색 카드를 연결하는 구조다.

Firecrawl 수집은 연결 계정의 크레딧 부족으로 실패했다. 이후 공개 홈페이지 HTML, 홈페이지가 직접 참조한 CSS 2개, 공식 Thumbprint 문서를 읽어 작성했다. 브라우저 스크린샷과 실행 후 computed style은 확보하지 않았으므로 **픽셀 단위 시각 검증을 마친 문서로 보아서는 안 된다.** 로그인 이후 화면, 실제 검색 결과, 견적·결제 흐름은 조사 범위 밖이다.

| 표시 | 의미 | 사용할 때의 기준 |
|---|---|---|
| **현행 소스** | 수집 당시 홈페이지 HTML에 연결된 클래스와 CSS 선언을 확인 | 홈페이지 재현의 우선 근거. 실행 시 최종 스타일은 추가 검증 필요 |
| **공식 규격** | 공개 Thumbprint 문서에서 확인 | 버전과 플랫폼을 확인한 뒤 적용 |
| **구현 제안** | 관찰된 패턴을 재사용하기 위해 이 문서에서 설계 | 원본에서 추출한 값으로 취급하지 않음 |

**값 충돌 시 우선순위:** 해당 홈페이지 요소의 구체적인 CSS → 공통 CSS → 같은 버전의 공식 문서 → 구현 제안.

공식 v1·v2 토큰과 홈페이지의 일부 사용자 정의 값이 공존한다. 특히 **브랜드 파란색 `#009FD9`와 홈페이지 검색 버튼 배경 `#07344A`를 동일하게 취급하지 않는다.**

## 2. 디자인 방향과 페이지 구성

### 2.1 재현해야 할 특징

1. **집과 실제 작업을 중심에 둔다.** 첫 화면의 주인공은 공간 사진이며, 검색 영역은 사진 위에서 명확하게 읽힌다.
2. **검색을 가장 중요한 행동으로 만든다.** 프로젝트 설명과 지역 입력을 가까이 배치하고 하나의 강한 CTA로 연결한다.
3. **신뢰 정보를 행동 가까이에 둔다.** 검색 바로 아래에 연락 정책과 평가·활동 규모를 배치한다.
4. **정보 계층을 색보다 크기와 간격으로 만든다.** 대부분은 흰색·회색·짙은 본문색, 강조는 파랑·짙은 청색으로 제한한다.
5. **모바일에서는 구조를 바꾼다.** 데스크톱의 사진 위 흰 글씨를 단순 축소하지 않고, 사진과 밝은 검색 패널을 나눈다.

### 2.2 페이지 구조

| 영역 | 수집 자료에서 확인한 내용 | 재사용할 설계 원칙 |
|---|---|---|
| 헤더 | 로고, 서비스 탐색, 전문가 참여, 로그인·가입; 좁은 화면의 메뉴 버튼 | 고객 행동과 공급자 행동을 구분 |
| Hero | 공간 사진, 제목, 설명, 프로젝트·지역 검색 | 첫 화면에서 무엇을 입력해야 하는지 분명하게 안내 |
| 신뢰 영역 | 연락 정책 안내, 평가·전문가·프로젝트 관련 지표 | 검증 가능한 실제 지표만 사용 |
| 서비스 탐색 | 서비스 종류별 탐색 및 일부 응답의 즉시 예약 섹션 | 위치·실험군에 따라 달라지는 콘텐츠를 데이터로 관리 |
| 장점 설명 | 매칭, 지역 전문가, 보증과 관련한 설명 | 추상적 홍보보다 사용자의 불안을 해소 |
| 프로젝트·자료 탐색 | 프로젝트 분류, 비용·유지관리·작업 가이드 | 카드 제목만 읽어도 이동 목적을 알 수 있게 구성 |
| 지역 탐색 | 도시·지역별 서비스 링크 | 긴 링크 목록을 별도 구역으로 정리 |
| 앱 안내·푸터 | 앱 설치 경로와 기업·정책 정보 | 보조 행동은 주 검색 CTA보다 낮은 시각적 우선순위 |

홈페이지 응답과 검색 인덱스에는 서로 다른 서비스 섹션 구성이 나타났다. 지역화 또는 실험 여부는 확정하지 못했으므로 한 종류의 페이지 순서를 전체 서비스의 고정 규격으로 단정하지 않는다. [S1, S12]

### 3.2 공식 v2와 홈페이지의 개별 예외

공통 CSS의 `:root`에는 공식 v2와 일치하는 의미별 토큰이 이미 포함돼 있다. 그 위에 특정 컴포넌트가 다른 값을 직접 지정한다. 아래 표는 사이트 전체와 v2가 분리돼 있다는 뜻이 아니라 **개별 예외와 공통 토큰의 차이**다.

| 역할 | 홈페이지 소스의 대표 값 | 공식 v2의 대응 규격 |
|---|---|---|
| 기본 본문 / 일부 기존 요소 | `body: #1F2022`, 모바일 Hero 제목 `#2F3033` | `--tp-text-neutral-default: #1F2022` |
| 기본 테두리 | 검색 영역 `#D3D4D5` | `--tp-border-neutral-default: #DDDEE1` |
| 주 행동 배경 | `#07344A` | `--tp-background-brand-strong: #07344A` |
| 주 행동 위 글씨 | `#B3EBFF` | `--tp-text-on-brand-strong: #7CDCFD` |
| 일반 링크 | 컴포넌트별로 다름 | `--tp-link-brand-default: #0175A3` |
| 밝은 브랜드 표면 | 컴포넌트별로 다름 | `--tp-background-brand-low: #E0F4FE` |

**홈페이지 재현은 개별 예외까지 유지하고, 새 제품의 v2 도입은 공통 토큰을 기준으로 한다.** 서로 다른 값을 임의로 섞어 한 버전의 공식 토큰이라고 표시하지 않는다. 공통 CSS에는 다크 테마 규칙도 있지만, 홈페이지에 사용자용 다크 모드 전환 기능이 있다는 뜻은 아니다. [S2, S4]

### 3.3 대비 검토

다음은 불투명 단색 두 개를 WCAG 상대 휘도 공식으로 계산한 결과다. 사진 위 글씨는 배경 사진과 오버레이를 함께 측정해야 한다.

| 전경 / 배경 | 계산한 대비 | 구현 판단 |
|---|---:|---|
| `#009FD9` / 흰색 | 약 3.02:1 | 보통 크기의 본문에 사용하지 않음 |
| `#0175A3` / 흰색 | 약 5.15:1 | 일반 링크 후보 |
| `#2F3033` / 흰색 | 약 13.20:1 | 기본 본문 후보 |
| `#676D73` / 흰색 | 약 5.23:1 | 보조 문구 후보 |

보통 크기 텍스트는 4.5:1 이상을 기준으로 검토한다. 오류·성공은 색상만 바꾸지 말고 아이콘과 설명을 함께 제공한다. [S7]

## 4. 타이포그래피

### 4.1 실제 홈페이지 폰트

**현행 소스:** 공통 CSS의 `@font-face`는 `Rise` 가변 글꼴, 굵기 범위 `100–900`을 선언한다. 참조 경로는 `https://fonts.thumbtack.com/thumbtack-rise/v10/ThumbtackRiseVF.woff2`다. CSS 참조는 확인했으나 폰트 파일의 실제 렌더링 결과는 확인하지 않았다. [S2]

기본 스택은 `Rise, Avenir, Helvetica, Arial, sans-serif`, `body` 크기는 `16px`, 행간은 `1.4`다.

기존 공식 typography 가이드에는 Rise의 `400/700` 두 굵기가 설명돼 있다. 반면 홈페이지는 `563`, `650` 같은 중간 굵기도 사용한다. **기존 가이드의 400/700 설명만으로 현재 홈페이지를 구현하면 제목 인상이 달라질 수 있다.** [S5]

### 4.2 홈페이지 타입 명세

| 요소 | 크기 | 행간 | 굵기 | 자간·비고 |
|---|---:|---:|---:|---|
| 데스크톱 Hero 제목, 482px 이상 | 48px | 1.05 | 563 | −0.96px, 흰색, 균형 줄바꿈 |
| 동일 제목의 기본 CSS 선언 | 36px | 1.05 | 563 | −0.02em; 481px 이하에서는 해당 패널이 숨겨짐 |
| 모바일 Hero 제목 | 28px | 32px | 700 | 자간 0, `#2F3033` |
| 데스크톱 Hero 설명 | 16px | 1.2 | 650 | 최대 너비 460px, 흰색 |
| 모바일 Hero 설명 | 16px | 24px | 400 | `#595C61` |
| 검색 안내 문구 | 16px | 1.5 | 400 | `#676D73` |
| 연락 정책 안내 | 14px | 1.4 | 400 | 데스크톱 흰색 / 모바일 회색 |
| 데스크톱 신뢰 지표 숫자 | 28px | 1.1 | 563 | −0.02em |
| 모바일 신뢰 지표 숫자 | 16px | 1.2 | 650 | 자간 0 |
| 사진 캡션 | 12px | 18px | 400 | 제목 역할 캡션은 700 |
| 하단 섹션 제목 Type title1 | 36 → 48px | 1.05 | 563 | 701px 이상 확대, −0.02em |
| 자료 카드 제목 Type title3 | 22 → 24px | 1.1 | 590 | 701px 이상 확대, −0.01em |

| 일반 본문 Type text1/2/3 | 16 / 14 / 12px | 1.4 | 상속·컴포넌트에 따름 | 크기·행간에 `!important` 적용 |

근거: `.hero-header_*`, `.hero-header-mobile_*`, `.hero-stats_*`, `.hero-caption_*` [S3]. 버튼 내부에는 별도 Type 클래스가 있으므로 부모의 `font-weight`만으로 라벨의 최종 굵기를 단정하지 않는다.

### 4.3 한국어 프로젝트 적용 제안

- 본문 대체 스택: `"Pretendard Variable", Pretendard, "Noto Sans KR", system-ui, sans-serif`.
- 대체 폰트는 프로젝트에서 별도로 설치한다. CSS에 이름만 적어서는 내려받아지지 않는다.
- 한국어 Hero는 모바일 `28–32px`, 넓은 화면 `40–48px` 범위에서 문장 길이로 결정한다.
- 한국어 본문은 `16px / 1.5–1.6`, 제목은 `1.15–1.3`부터 검토한다. 이는 원본 값이 아닌 가독성 조정안이다.
- 한글 줄바꿈은 `word-break: keep-all; overflow-wrap: anywhere`를 검토한다. 긴 URL과 영문 서비스명도 함께 시험한다.
- Rise를 다른 서비스에 포함하려면 폰트의 사용 범위를 별도로 확인한다. 원본 폰트를 복사하지 않아도 크기·굵기·간격 구조는 재현할 수 있다.

## 5. 레이아웃과 반응형

### 5.1 컨테이너

**현행 소스의 공통 Wrap:** `width:100%`, `max-width:946px`, 가운데 정렬, 기본 좌우 패딩 `16px`, `482px` 이상 `32px`, `1011px` 이상 패딩 `0`. 전역 `border-box`를 상속하므로 **946px에는 해당 시점의 패딩이 포함된다.** 콘텐츠 너비에 패딩을 다시 더하지 않는다. [S2]

Hero 사진은 화면 전체 폭을 사용하고, 제목과 검색은 Wrap 안에서 정렬된다. Hero 검색의 최대 너비는 `588px`, 설명은 `460px`다. 전체 화면을 무조건 946px로 제한하면 사진이 원본과 다르게 보인다. [S3]

**공식 v1 Grid:** 12열, 기본 gutter `16px`, 선택값 `32px` 또는 `0`; 좁은 화면에서 세로 적층. 이는 공식 레이아웃 도구의 규격이며 홈페이지 모든 섹션이 12열로 작성됐다는 의미는 아니다. [S6]

### 5.2 실제 반응형 경계

| 범위·경계 | 확인한 규칙 |
|---|---|
| `max-width: 481px` | 모바일 Hero 패널, 사진과 텍스트 분리, 사진 높이 212px, 사진 캡션 숨김 |
| `min-width: 482px` | 데스크톱 Hero 제목 48px, 사진 위 검색 패널, Wrap 좌우 패딩 32px |
| `max-width: 700px` | 동적 Hero 최소 높이 `100dvh` |
| `min-width: 701px` | 헤더의 데스크톱 링크 표시; 주요 Type 제목 확대; 프로젝트 카드 3열 |
| `min-width: 1011px` | Wrap 좌우 패딩 0, 가운데 고정 폭 유지 |
| 기본 Hero | 최소 높이 `calc(100dvh - var(--global-header-height, 72px))` |

공식 v2 코어 분기점은 `481/700/1025px`이며 split-view는 `769/1060px`다. 이 숫자를 현재 홈페이지 CSS의 `482/1011px` 대신 일괄 대입하지 않는다. [S2–S4]

### 5.3 간격·둥글기

| 범주 | 공식 v2 값 | 이 문서의 활용 제안 |
|---|---|---|
| 간격 | `4, 8, 12, 16, 20, 24, 32, 48, 64, 96, 128, 256px` | 작은 내부 간격 8–16, 카드 간격 16–24, 섹션 간격 48–96 |
| 모서리 | `0, 4, 6, 8, 12, 16, 24, 9999px` | 검색 상자 16, 이미지 카드 8–16, CTA pill 9999 |
| 그림자 100 | `0 1px 3px rgba(0,0,0,.1)` | 낮은 높이의 표면 |
| 그림자 200 | `0 2px 4px rgba(0,0,0,.15)` | 필요할 때만 높이 차이를 표시 |

표의 활용 제안은 토큰을 컴포넌트에 매핑한 설계안이다. 실제 홈페이지 값으로 확인한 대표 사례는 모바일 Hero 패널 `padding:24px 16px 32px`, 그룹 gap `24px`, 제목·설명 gap `4px`, 검색 영역과 텍스트 그룹 사이 gap `32px`다. [S3, S4]

## 6. 컴포넌트 명세

### 6.1 헤더와 메뉴

**현행 소스:** 넓은 화면은 로고와 탐색·계정 링크, 좁은 화면은 메뉴 버튼과 세로 링크 목록을 준비한다. 메뉴 버튼에는 접근 가능한 이름이 있다. [S1]

헤더 분기는 `701px`이다. 데스크톱 헤더의 높이 기본 대체값은 `72px`, 기본 헤더는 `60px`이며 `--global-header-height`로 덮어쓸 수 있다. 모바일 변형은 투명 그라데이션 배경과 하단 테두리 제거 규칙을 갖는다. 헤더의 작은 계정 버튼은 `min-height:40px`, 공통 큰 버튼은 `min-height:52px`이므로 아래의 공식 v1 버튼값과 구분한다. [S2]

**구현 제안:** 로고는 홈 링크, 탐색은 링크 또는 메뉴 버튼으로 구현한다. 이동용 링크 안에 또 다른 버튼을 중첩하지 않는다. 모바일 메뉴에는 열림 상태, 닫기, Escape 처리, 초점 이동·복귀를 함께 구현한다. 헤더 전환점을 Hero 전환점과 무조건 같다고 가정하지 않는다.

### 6.2 Hero 검색

| 요소 | 현행 소스 명세 |
|---|---|
| 데스크톱 검색 영역 | 최대 588px; 흰 배경; 테두리 1px `#D3D4D5`; radius 16px; 내부 여백 16px |
| 검색 하단 행 | 지역 입력 + CTA; gap 12px; 상단 여백 12px |
| 모바일 검색 구조 | 검색 열기 버튼 + 지역 입력 + CTA의 별도 구성 |
| 모바일 검색 표면 | 흰색; radius 24px; padding 16px; 내부 gap 36px; 테두리 회전 효과 선언 |
| 모바일 지역 입력 | 높이 48px; 좌우 여백 20px; 테두리 1.5px `#DDDEE1`; pill |
| 모바일 지역값 너비 | `5ch`; 미국 우편번호를 위한 값 |
| 접근성 | 검색·지역 필드의 이름, 검색 열기 버튼의 이름 확인 |

한국 서비스에서는 `5ch` 우편번호 필드를 그대로 쓰지 말고 시·군·구 또는 주소 선택 흐름으로 교체한다. 모바일 검색 버튼을 누른 뒤의 실제 런타임 전환은 이번 조사에서 실행하지 않았다. [S1–S3]

**구현 제안 상태:** 기본 → 포커스 → 입력됨 → 결과 제안 → 조회 중 → 결과/빈 결과/오류. 검색 실패 시 기존 입력을 유지하고 재시도 경로를 제공한다. 로딩 중 중복 요청을 막되 입력값을 지우지 않는다.

### 6.3 주 행동 버튼

| 속성 | 데스크톱 Hero CTA | 모바일 Hero CTA |
|---|---|---|
| 높이 | 40px | 48px |
| 좌우 패딩 | 20px | 16px |
| 배경 / 글씨 | `#07344A` / `#B3EBFF` | 동일 |
| 아이콘 | 18px | 18px |
| 모서리 | 공통 검색 버튼의 radius 76px | 9999px |
| hover | `#094D6B` | 같은 선언 확인 안 됨 |
| active | `#052A3A`, `scale(.98)` | 같은 선언 확인 안 됨 |
| focus | 2px `#009FD9`, offset 2px | `focus-visible`에 동일한 링 |

**공식 v1 Button**의 일반 규격은 큰 버튼 48px, 작은 버튼 32px이다. 홈페이지 CTA의 40px을 “공식 공통 버튼 높이”로 확대 해석하지 않는다. [S2, S3, S7]

**구현 제안:** 화면의 주 행동은 하나만 강하게 강조한다. 긴 한국어 라벨 때문에 줄바꿈이 발생하면 높이를 억지로 고정하지 않는다. 비활성·로딩·완료·오류 상태를 기본 버튼과 함께 설계한다.

### 6.4 신뢰 지표

**현행 소스:** 데스크톱은 흰색 숫자와 설명을 사진 위에 놓고, 모바일은 밝은 패널에서 짙은 숫자와 회색 설명을 사용한다. 숫자와 설명은 세로로, 지표들끼리는 가로로 배열하고 줄바꿈을 허용한다. [S3]

**구현 제안:** 별점, 표본 수, 집계 기간을 명확히 구분한다. 참고 사이트의 리뷰·전문가·프로젝트 수치는 다른 제품의 샘플 실적으로 재사용하지 않는다.

### 6.5 카드·탭·하단 섹션

| 요소 | 현행 소스 명세 | 구현 시 주의 |
|---|---|---|
| 서비스·자료 카드 | radius 16px, 이미지 cover, 넘치는 부분 숨김 | 카드 종류별 높이를 하나로 통일하지 않음 |
| 작은 이미지 카드 | 기본 높이 228px, 482px 이상 290px | 실제 이미지의 중요 부분 잘림 확인 |
| 큰 자료 카드 | 기본 높이 228px, 482px 이상 400px | 너비 304px 선언과 `w-100 !important`가 충돌하므로 최종 너비를 304px로 단정하지 않음 |
| 이미지 위 카드 텍스트 | 하단 그라데이션·blur 2px; 상단 24px, 하단·좌우 16px | 사진이 바뀌면 대비 재검토 |
| 프로젝트 카드 그리드 | 기본 2열, 701px 이상 3열; gutter 16px | 작은 화면에서 긴 제목 줄바꿈 확인 |
| 카테고리 탭 | 기본 회색; 활성 짙은 본문색과 파란 하단 표시 4px; 아이콘 28px | 색과 하단 표시를 함께 사용 |
| 탭 간격 | 기본 오른쪽 36px, 482px 이상 48px | 좁은 화면의 수평 탐색 단서 유지 |
| 주요 하단 섹션 | `pv6`로 상하 64px; 일부 배경 `#FAFAFA` | section 배경과 모바일 Hero 배경을 구분 |
| 신뢰 설명 카드 | padding 32px, radius 16px, 기본 테두리 1px `#676D73` | 482px 이상에는 투명 테두리·최소 폭 416px 선언이 있으므로 실제 배치 확인 |

이미지 카드에는 hover 시 `scale(1.1)`과 0.3초 전환이 선언돼 있다. 구현 제안으로는 가려짐·레이아웃 흔들림을 확인하고, 필요하면 확대를 이미지 내부에 제한하거나 1.02 정도로 줄인다. 모션 감소 설정에서도 카드 효과를 끄도록 보완한다.

탭은 원본의 수평 스크롤·숨김 CSS만 확인했으며 키보드 동작은 검증하지 않았다. 콘텐츠 패널을 바꾸는 탭으로 구현한다면 선택 상태, 방향키 이동, 패널 연결을 함께 구현한다. 카드 제목에도 Type 유틸리티의 `!important`가 붙어 있으므로 모듈 CSS에 적힌 20px만 보고 최종 글자 크기를 판단하지 않는다. [S1–S3]

### 6.6 알림·모달·입력 상태

홈페이지 HTML에서 검색 모달용 마크업과 알림용 구조는 확인했지만, 오류 발생·전송·완료 등의 실제 상호작용은 실행하지 않았다. 아래는 구현 제안이다.

| 상태 | 표현·동작 |
|---|---|
| 오류 | 필드 가까이 원인과 수정 방법; `aria-invalid`와 설명 연결 |
| 성공 | 완료 메시지와 다음 행동; 색만으로 알리지 않음 |
| 로딩 | 버튼 너비 유지, 중복 전송 방지, 상태 읽기 지원 |
| 빈 결과 | 검색어나 지역 수정 경로 제공 |
| 모달 | 제목 연결, 초점 관리, Escape, 닫은 뒤 초점 복귀 |
| 비활성 | `disabled` 또는 상황에 맞는 `aria-disabled`; 사용 불가 이유 제공 |

## 7. 이미지·아이콘·움직임

### 7.1 이미지

**현행 소스:** Hero 이미지는 `object-fit:cover`, 데스크톱은 한쪽이 어두워지는 오버레이를 사용한다. 모바일은 사진을 212px 높이의 별도 블록으로 표시한다. 사진 캡션에는 반투명 검정 배경, blur 5px, radius 16px, padding 16px가 선언돼 있다. [S3]

**구현 제안:** 집·작업 장면·완료된 결과를 보여주는 사진을 선택한다. 주요 인물이나 작업 대상이 잘리지 않도록 화면별 `object-position`을 조정한다. 이미지가 정보를 전달하면 대체 텍스트를 제공하고, 순수 장식이라면 빈 대체 텍스트를 사용한다. 로고·사진·폰트 파일은 디자인 규칙과 별개의 자산으로 관리한다.

### 7.2 아이콘

홈페이지 지역·검색 CTA 아이콘의 `18px` 규격을 확인했다. 공식 기존 아이콘 규격은 `14/18/28px`다. 같은 역할의 아이콘은 크기·획 두께를 통일하고 아이콘만 있는 버튼에는 접근 가능한 이름을 준다. 다른 아이콘 라이브러리를 사용할 경우 공식 Thumbprint 아이콘과 동일하다고 표시하지 않는다. [S2, S3, S8]

### 7.3 모션

| 위치 | 현행 CSS 선언 | 재사용 판단 |
|---|---|---|
| Hero 이미지 교체 | opacity 0.7초 | 교체 주기와 실제 자동 실행 여부는 미검증 |
| Hero 사진 확대 | 12초 동안 scale 1 → 1.1 | 분위기 효과; 저사양·접근성 설정에서는 제거 가능 |
| 고정 검색바 | 0.2초 이동·투명도 전환 | 표시 조건의 JS 로직은 미검증 |
| CTA 누름 | scale .98 | 짧은 피드백으로 사용 |
| reduced motion | 주요 Hero·캡션 효과를 끄는 규칙 존재 | 신규 효과에도 동일하게 적용 |

공식 일반 모션 토큰은 `75/150/200/250/300/350ms`다. 홈페이지의 700ms·12초 효과는 별도 연출값이다. 두 체계를 하나의 시간 규칙으로 혼동하지 않는다. [S3, S4]

## 8. 재사용용 CSS 시작점

다음 코드는 원본 CSS 복사본이 아니라 **확인한 값으로 정리한 독립적인 시작점**이다. 별칭, 클래스 이름, 한국어 폰트 스택, 상태 보완은 이 문서의 구현 제안이다. 원본 사이트의 동작·사진·자산은 포함하지 않는다.

## 9. 적용 방법 3가지

| 방식 | 선택할 상황 | 적용 기준 | 한계 |
|---|---|---|---|
| **A. 홈페이지 재현** | Thumbtack과 비슷한 서비스 탐색 화면 제작 | 현행 소스의 검색·사진·모바일 분리 구조 우선 | 스크린샷 기반 최종 비교가 추가로 필요 |
| **B. 공식 v2 기반 신규 구축** | 여러 화면에 일관된 UI 체계가 필요 | 의미별 색상·타입·간격을 v2로 통일 | 현재 홈페이지와 시각적으로 완전히 같지는 않음 |
| **C. 한국어 서비스에 맞춘 변형** | 국내 견적·예약·전문가 매칭 제품 | A의 정보 구조 + 한국어 폰트·주소·실제 신뢰 지표 | 원본 값과 변형값을 프로젝트 토큰에서 구분해야 함 |

이 요청의 기본 산출물은 A를 중심으로 한다. 실제 국내 제품 개발에 사용할 때는 C가 관리하기 쉽다. B를 선택하면 새 화면에 v1 타입·색을 무심코 가져오지 않도록 버전 규칙부터 정한다.

## 10. 구현 순서와 검수

### 10.1 구현 순서

1. A/B/C 중 기준을 정하고 토큰을 한 파일로 고정한다.
2. 폰트와 Wrap, 기본 텍스트·링크·버튼을 먼저 구현한다.
3. 데스크톱 Hero와 모바일 Hero를 각각 구성한다.
4. 검색의 지역 입력·로딩·오류·빈 결과를 연결한다.
5. 카드·탭·신뢰 영역·지역 탐색·푸터를 동일한 토큰으로 조합한다.
6. 실제 사진·한국어 문구를 넣은 뒤 화면 폭과 키보드 조작을 검수한다.

### 10.2 실패하기 쉬운 부분

| 문제 | 생기는 결과 | 개선 방법 |
|---|---|---|
| 공통 스타일만 읽고 개별 override를 무시 | 검색 버튼이 청색 대신 밝은 파랑으로 구현됨 | DOM 클래스와 가장 구체적인 선택자를 연결 |
| 공식 v1·v2를 혼합 | 제목 굵기·간격·본문색이 화면마다 달라짐 | 선택한 버전과 예외값 기록 |
| 모바일을 단순 축소 | 사진 위 텍스트·입력 영역이 과밀해짐 | 별도 패널 구조와 212px 사진 블록 검토 |
| 작은 글씨에 브랜드 파랑 사용 | 흰 배경 대비 부족 | 일반 링크에는 더 어두운 색 사용 |
| 영문 폰트 수치를 한글에 그대로 적용 | 제목이 너무 빽빽하거나 줄 수 증가 | 폰트 로딩 후 행간·줄바꿈 재조정 |
| 이미지·모션만 따라 만들기 | 검색 실패·빈 결과에서 흐름 단절 | 입력부터 결과까지 상태 설계 |
| 원본의 큰 z-index를 그대로 복사 | 검색바가 모달을 가림 | 프로젝트 전체 overlay 우선순위 설계 |

### 10.3 완료 체크리스트

- [ ] 360·390·481·482·700·701·1010·1011·1440px 폭에서 가로 넘침이 없다.
- [ ] Hero의 모바일/데스크톱 분기와 헤더 분기를 각각 확인했다.
- [ ] 폰트 로딩 전후 제목·버튼·입력의 크기 변화가 허용 범위다.
- [ ] 긴 한국어 제목, 긴 지역명, 영문 서비스명도 잘리지 않는다.
- [ ] 버튼·링크·입력을 키보드로 이용하고 초점을 확인할 수 있다.
- [ ] 검색 실패·빈 결과·느린 응답·중복 클릭을 처리한다.
- [ ] 사진 위 텍스트는 실제 사용 이미지마다 대비를 확인했다.
- [ ] 이미지 교체·사진 확대는 모션 감소 설정을 존중한다.
- [ ] 메뉴·검색 모달을 닫으면 원래 위치로 초점이 돌아온다.
- [ ] 데스크톱·모바일 대표 스크린샷을 기준 화면과 비교했다.

위 체크리스트는 **향후 구현 검수 항목**이며, 이번 문서 작성 과정에서 모두 통과했다는 의미가 아니다.
